## Уточнённый порядок внешней приёмки (решение пользователя)

Пользователь выполняет команды сам через SSH и присылает обезличенные результаты.
SSH/токен не запрашиваем. Сначала Debian 13 + **cloud**, local и Debian 12/Fake-IP
позже. По последнему явному поручению пользователя config.yaml в Git теперь имеет
default cloud; local остаётся явным выбором. Нормативные документы не изменены.
Сценарий и первый read-only шаг — `docs/CLOUD_ACCEPTANCE.md`.

Исправлена процедура подготовки: фиксированный ExecStartPre --if-requested в
окончательном юните, root-owned helper запускается системным Python -I вне рабочего
дерева; запрос/отчёт привязаны к boot/hash/InvocationID. Отсутствующий listener/IPv6
не считается PASS, проверяются оба семейства и дети; baseline перепроверяется под
UID tgbot вне worker. Изменять unit после пробы нельзя. .env/config не копируются
поверх существующих; добавлена read-only проверка прав. Нормативные файлы не менялись.
Локальная регрессия после этих исправлений: 100 тестов PASS на Python 3.13.5;
compileall/diff --check PASS. Это не результаты VPS.

## Исправление развёртывания по результату пользователя

На Debian 12 / Python 3.11 пользователь сообщил PermissionError при создании logs
в root-owned проекте. Процедура теперь до любого запуска создаёт logs (и остальные
рабочие каталоги) tgbot:tgbot 0700; код и venv устанавливает администратор, без
рекурсивного chown в пользу сервиса. Preflight требует logs и отклоняет доступные
сервису на запись исходники/venv. Default config.yaml изменён на cloud по явному
поручению пользователя; поддержка explicit local и схема изоляции не менялись.

Проверки этой правки: 42 целевых теста PASS; полная регрессия 107 тестов PASS
на Python 3.13.5; compileall/diff --check PASS. Debian 12/Python 3.11 здесь
повторно не проверялись: интерпретатор 3.11 отсутствует. Юниты, механизм
подтверждения и оба нормативных документа без изменений.

## Исключение trusted_users из лимита ссылок

По явному поручению пользователя trusted_users освобождаются и от дневной квоты,
и от link attempts/временной блокировки (уточнение ТЗ §11/§17 без редактирования
самих нормативных файлов). Единая проверка Store._link_allowed применяется из
intake и rate_allow; Broker передаёт только validated config trusted_users.
Дедупликация received_updates выполняется первой в той же транзакции. Доверенные
попытки не записываются; старые bans/attempts сохраняются, но игнорируются до
исключения ID из списка. URL/очередь/worker/права/Telegram API не обходятся.

Целевые проверки: 29 PASS (новые trusted/regular сценарии плюс state/recovery).
Полная регрессия: 120 тестов PASS на Python 3.13.5; compileall и diff --check PASS.
Все production-вызовы intake/rate_allow проверены; config.yaml, security units и
механизм подтверждения изоляции не изменены.
Ручную приёмку Debian 12/Python 3.11 пользователь сообщил как успешную до этой
правки; новый код на его VPS разработчиком не выполнялся.
